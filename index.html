From Silicon to SustainabilityAn Agentic Framework for Green and Quality-Aware Edge LLMOps

A pipeline that measures the energy cost of training any model, scores every run out of 100, and lets an LLM agent decide what to change next, but only after an evaluation gate says the agent can be trusted. LightGBM is the model used in this study.

Overview

  • 100point score

    Carbon, quality, efficiency and trend in one number per run.

    Recomputed on every upload
  • 3×agent samples

    The gate asks the same question three times and checks agreement.

    All checks must pass
  • 0external APIs

    The agent runs a local Ollama model, llama3.2:3b, in the cluster.

    No per-request cost

In this study the task is air quality: a binary label predicted from sensor readings. Training and inference are metered separately, converted to CO₂, and published to Pub/Sub for the Optimise Agent.

Architecture

Every arrow is a message or a table write. Recommendations never change the run that produced them; they wait as PENDING until the next upload.

Works with any model

The agent only sees a score, its factors and the parameters used, so it does not care what produced them. The reference implementation trains LightGBM directly. To use another model, supply four things:

Honest scopeThe code in this study calls LightGBM and uses tree counts directly. Making it model-agnostic means replacing the training function, the complexity unit and the parameter ranges the agent may recommend.

Pipeline

  1. Load the CSV, forward-fill short gaps, derive the label from the threshold.
  2. Features: 8 sensors with lag-1 and lag-24 copies plus hour and weekday cycles.
  3. Chronological split: 70% train, 10% validation, 20% test.
  4. Train while metering energy; evaluate; run inference on all rows while metering again.
  5. Score, log, publish.
busy_cores = (user + system CPU seconds) / wall seconds   # floor 0.05
watts      = 15 W × busy_cores
energy_kwh = watts × duration_s / 3,600,000
co2_kg     = energy_kwh × GRID_INTENSITY_G_PER_KWH / 1000 # default 400
An estimate, not a measurementFixed 15 W per busy core and constant grid intensity. Good for comparing runs, not for carbon reporting.

Green Score

Hover a row to light up its segment above.

FactorMaxFormula

Factors are floored at 0 and the total is capped at 100. Ratings: 70+ Good, 40 to 69 Fair, below 40 Poor.

Scores saturate with the defaultsBaselines are CO2_BASELINE=0.001, CO2_PER_ROW_BASELINE=1e-7, ENERGY_PER_TREE_BASE=1e-6, THROUGHPUT_BASELINE=1e6. A small job uses far less, so carbon factors sit near maximum. Recalibrate from your own history.

Optimise Agent

One structured-JSON call to Ollama per decision, using the last 7 runs. Hover a card for the rule.

  • monitorEverything is healthy.Score 90+, trend stable or up
  • investigateOne factor needs attention.Score 70 to 89
  • interveneScore is low.Score below 70
  • alertQuality is slipping.Trend consistently declining
  • rescheduleCarbon keeps scoring badly.Carbon below 10 for 3+ runs
  • retrainThe model is degrading.F1 declining over recent runs

Infrastructure actions run only after the gate passes: scale_replicas (1 to 3 replicas) and switch_llm (allow-listed models only). RBAC permits nothing else.

FallbackIf Ollama is down or returns invalid JSON, a rule-based decision is logged. It always fails the gate, never recommends parameters and never triggers infrastructure actions.

Parameter control

Recommendations are validated (N_TREES 50 to 500, WHO_THRESHOLD 1.7 to 10.0) and stored as PENDING. The trigger uses the newest PENDING row, then the newest APPLIED, then defaults (500 and 5.0), and marks a row APPLIED only after the Job is created. A newer recommendation builds on a pending one instead of replacing it.

Evaluation gate

A new run has no reference answer, so the gate measures consistency across 3 samples. It passes only if every check passes. Hover a check.

  • llm_availableNo sample used the fallback.0 fallbacks
  • rouge_lLongest common subsequence.0.35 or more
  • bleun-gram precision overlap.0.15 or more
  • semantic_simTF-IDF cosine similarity.0.55 or more
  • bias_stabilitySame action and priority each time.0.66 or more
  • latencySlowest single call.90 s or less

Thresholds are set through environment variables. Semantic similarity uses TF-IDF cosine by default; BERTScore can replace it when enabled and installed.

Limitations

  • Energy and CO₂ values are model-based estimates. Calibrate them for the target hardware and region.
  • The Green Score is a project-defined composite, not a standardised environmental certification.
  • Consistent LLM output does not guarantee correctness. Review recommendations and monitor later runs.
  • Parameter experiments are separate from the production trigger and agent flow.
  • Review resource names, IAM permissions, SQL schemas and manifests before deploying to a new project.
